# AGENTS.md — контекст для AI-агентов

## Что это за репозиторий

**30 Highload Engineering Challenges** — hands-on лаборатория по distributed systems.  
Это учебный проект: **качество подтверждается понятным кодом и проверяемыми экспериментами**. Явные паттерны и архитектурные границы помогают исследовать поведение; готовность к эксплуатации оценивается отдельно для конкретных требований и условий.

Автор параллельно изучает Go, system design и декомпозицию систем. Код и комментарии должны помогать **возвращаться к задаче через время** и быстро вспоминать «что и зачем».

## Стек и структура

| Область | Расположение |
|---------|--------------|
| Go-лабы | `01-…`, `02-anti-bruteforce/go`, `03-worker-pool/go`, `04-idempotency/go`, … |
| Node-лабы | `01-atomic-inventory/node`, … |
| Общий Go-код | `shared/go/` (`labshared` module) |
| Workspace | `go.work` в корне |
| Теория / план | `IMPLEMENTATION_GUIDE.md`, `docs/` внутри каждой задачи |

## Архитектурный контракт (Go)

1. **Hexagonal**: domain → usecase → adapters (inbound HTTP, outbound infra).
2. **Composition root**: `internal/di/app.go` — единственное место сборки зависимостей.
3. **Strategy subtasks**: naive/noop → bounded/memory → redis → advanced — отдельные реализации одного интерфейса.
4. **Shared HTTP**: `labshared/httpx` — JSON-ответы и ошибки для всех сервисов.

## Комментарии в коде

- Язык: **русский** (если пользователь пишет по-русски).
- Формат: **пошаговые этапы** + **зачем** (trade-off, риск, паттерн).
- Пример: handler с «Шаг 1… Шаг 5», middleware с потоком TryLock → fn → Complete.

Не писать очевидности. Писать то, что поможет через полгода понять решение без чтения всего diff.

## Чего не делать

- Дублировать логику в нескольких пакетах.
- Писать «лабораторный» код без структуры (всё в `main.go`).
- Игнорировать существующие соглашения соседних задач.
- Коммитить без явной просьбы пользователя.
